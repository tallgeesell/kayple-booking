# 상담 예약 서비스

1:1 상담(1시간) 예약 웹 서비스입니다. 상담실이 하나라서 한 시간에는 한 건만 예약할 수 있습니다.

- 사용자: https://ldj.recruit.kayple.com/
- 관리자: https://ldj.recruit.kayple.com/admin
- API: https://ldj.recruit.kayple.com/api/…

| 구분 | 기술 |
|---|---|
| Web | React 18 + Vite, react-router |
| Backend | Spring Boot 4 (Java 17+), Spring Data JPA, Bean Validation |
| DB | MySQL 8 (서버 설치본), 테스트는 H2(MySQL 모드) |
| 배포 | nginx(HTTPS, 정적 파일 + `/api` 프록시) → systemd로 Spring Boot 실행 |

---

## 실행 방법

### 로컬 개발

```bash
# 1) 백엔드: 로컬 MySQL 없이 H2 메모리 DB로 실행 (관리자 비밀번호는 원하는 값으로 지정)
cd backend
./mvnw spring-boot:run -Dspring-boot.run.useTestClasspath=true \
  -Dspring-boot.run.arguments="--spring.datasource.url=jdbc:h2:mem:local;MODE=MySQL;DB_CLOSE_DELAY=-1 --spring.datasource.username=sa --spring.datasource.password= --spring.jpa.hibernate.ddl-auto=create-drop --admin.password=<관리자비밀번호>"

# 2) 프론트: http://localhost:5173 (/api 는 8080으로 프록시)
cd frontend && npm ci && npm run dev
```

### 테스트

```bash
cd backend && ./mvnw test           # 서버 핵심 로직 20개

# 화면 E2E 43개 (Chrome 원격 디버깅으로 실제 화면 조작). 로컬 서버 2개를 켠 상태에서:
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --remote-debugging-port=9333 --user-data-dir=/tmp/e2e-chrome about:blank &
ADMIN_PW=<관리자비밀번호> bash e2e/seed.sh /tmp && ADMIN_PW=<관리자비밀번호> node e2e/e2e.mjs /tmp
```

E2E는 기준일 2026-11-25(수) 21시 이후, 빈 DB에서 실행하는 것을 전제로 작성했습니다.

### 서버 배포 (ldj.recruit.kayple.com)

최초 1회, 비밀값이 든 환경 파일을 서버에만 만듭니다. 이 파일은 Git에 없습니다.

```bash
sudo mkdir -p /etc/booking
sudo tee /etc/booking/booking.env >/dev/null <<'ENV'
DB_PASSWORD=<~/README-server.txt 의 app 비밀번호>
ADMIN_USERNAME=admin
ADMIN_PASSWORD=<관리자 비밀번호>
ENV
sudo chmod 600 /etc/booking/booking.env
git clone https://github.com/tallgeesell/kayple-booking.git ~/kayple-booking
```

이후 배포는 매번 아래 한 줄로 끝납니다. 테스트 → 빌드 → jar·정적 파일 교체 → 재시작 → 헬스체크 순서로 진행합니다.

```bash
~/kayple-booking/deploy/deploy.sh
```

- 백엔드: `/opt/booking/app.jar`, `booking.service`(systemd), 127.0.0.1:8080
- 프론트: `/var/www/booking` (SPA라서 `/admin`, `/my` 같은 경로는 index.html로 보냄)
- nginx: [deploy/nginx.conf](deploy/nginx.conf) (80 → 443 리다이렉트, Let's Encrypt 인증서)
- 로그: `sudo journalctl -u booking -f`

## 한 것

**사용자**
- 오늘부터 7일, 하루 10·11·13·14·15·16·17시를 예약할 수 있습니다(12시는 점심).
  - 이미 예약된 시간에는 **'마감'** 이 표시됩니다.
  - 오늘 이미 지난 시간은 '마감' 글자 없이 **비활성 모양**으로 보입니다(점선 + 취소선).
- 예약 정보로 이름과 연락처를 받고, 형식이 틀리면 해당 칸에 오류를 보여 줍니다. 서버도 같은 규칙으로 다시 검사합니다.
  - 이름: 한글(완성형)·영문·띄어쓰기만, 최대 20자. 숫자나 특수문자가 있으면 거절합니다.
  - 연락처: 하이픈 유무와 관계없이 받습니다. 010은 11자리만 받고, 011·016~019는 10·11자리 모두 받습니다.
- **중복 예약 방지**
  - 같은 시간: 이미 찬 시간에 제출하면 서버가 409와 함께 "이미 예약된 시간입니다…"를 돌려주고 화면에 배너로 보여 줍니다.
  - 같은 사람: 진행 중인 예약(대기·승인 상태이고 아직 지나지 않은 예약)은 연락처당 1건만 받습니다. 넘으면 **"이미 신청한 예약이 있습니다"** 팝업에 [닫기]와 [내 예약보기]를 띄웁니다.
- **자정 넘김**: 예약 화면을 연 채로 날짜가 바뀐 뒤 [다음]이나 [예약하기]를 누르면 "날짜가 바뀌었습니다" 팝업을 띄우고 일정을 다시 불러옵니다. 서버도 화면을 연 날짜(`viewedToday`)를 비교해서 거절합니다.
- **내 예약 확인**: 연락처로 조회합니다.
  - 예약 일시, 상태(대기·승인·취소됨), 신청 일시, 마스킹된 연락처를 보여 줍니다.
  - 관리자가 취소한 건은 취소 사유도 보여 줍니다.
  - 이미 지난 예약에는 취소 버튼이 없고, 서버에서도 취소를 막습니다.
- 연락처는 사용자·관리자 화면 모두 마스킹해서 보여 줍니다(`010-****-5678`).

**관리자 (`/admin`)**
- 아이디와 비밀번호로 로그인하고 세션 쿠키로 인증합니다. 계정은 하나뿐이고 가입 기능은 없습니다.
  - 로그인하지 않으면 `/api/admin/**` 는 **401** 만 돌려줍니다.
  - 비밀번호는 서버 환경변수(`ADMIN_PASSWORD`)로만 넣습니다. 값이 비어 있으면 로그인 자체를 막습니다.
- **캘린더**
  - 연도 이동과 1~12월 탭이 있고, 날짜 칸마다 대기·승인·취소 건수를 보여 줍니다.
  - 날짜 칸을 누르면 그날의 **목록 화면**(`/admin/YYYY-MM-DD`)으로 이동합니다.
- **목록 화면**
  - 대기 건을 **승인**할 수 있습니다.
  - 진행 중인 건은 **사유를 적어서 취소**합니다(사유 필수). 사유는 사용자 조회 화면에도 보입니다.
  - 비고 칸은 최대 2줄까지 보이고, 넘치면 '…'로 줄입니다. 줄어든 칸을 누르면 전문 다이얼로그가 뜹니다.
  - 전날·다음날 이동과 캘린더로 돌아가기를 지원합니다.

**중복 예약을 막는 방식**

화면에서 먼저 확인하는 것만으로는 동시에 들어온 요청을 막을 수 없습니다. 그래서 최종 판단은 **DB 유니크 제약**에 맡겼습니다.

| 컬럼 | 값 | 제약 |
|---|---|---|
| `active_slot` | 진행 중이면 `"2026-11-26-14"`, 취소되면 `NULL` | UNIQUE: 같은 시간 1건 |
| `active_phone` | 진행 중이면 연락처, 취소되거나 시간이 지나면 `NULL` | UNIQUE: 같은 사람 1건 |

MySQL 유니크 인덱스는 NULL끼리는 겹쳐도 허용합니다. 그래서 취소된 시간은 다시 예약할 수 있습니다. 시간이 지난 예약은 새로 신청할 때 `active_phone` 을 비워서 풀어 줍니다.

동시성은 테스트로 확인했습니다. 같은 시간에 10명이 동시에 신청해도 1건만 성공하고, 같은 사람이 7개 시간을 동시에 신청해도 1건만 성공합니다.

## 못 한 것 / 알고 있는 한계

- **본인 확인이 연락처뿐입니다.** 남의 번호를 알면 그 사람의 예약을 조회하고 취소할 수 있습니다. 실제 서비스라면 SMS 인증이나 예약 번호와 함께 확인하는 방식이 필요합니다.
- **관리자 비밀번호를 평문 환경변수와 비교합니다.** 해시 저장과 로그인 시도 횟수 제한(무차별 대입 방어)이 없습니다.
- **스키마는 `ddl-auto=update`** 로 만듭니다. 운영이라면 Flyway 같은 마이그레이션 도구로 바꿔야 합니다.
- 예약을 승인하거나 취소해도 사용자에게 알림이 가지 않습니다. 사용자는 직접 조회해야 합니다.
- 관리자가 예약을 대신 등록하거나 다른 시간으로 옮기는 기능은 없습니다.
- E2E는 기준일에 맞춘 고정 날짜로 작성해서, 다른 날에 돌리려면 날짜를 고쳐야 합니다. CI에 넣지 않았습니다.

## AI가 만든 코드 중 판단해서 바꾼 부분

**요구사항·정책 판단** (명세에 없거나 모호해서 직접 정한 것)

| 처음 AI가 만든 것 | 판단해서 바꾼 것 |
|---|---|
| 오늘 지난 시간도 '마감' 표시 | '마감'은 예약 찬 시간에만 쓰고, 지난 시간은 비활성 모양으로 구분. 자정 넘김은 팝업과 서버 검증으로 막음 |
| 같은 연락처로 여러 건 예약 가능 | 진행 중인 예약은 1인 1건. 팝업에서 내 예약으로 바로 이동 |
| 예약 즉시 확정 | 대기 → 관리자 승인 / 사유 입력 후 취소. 사유를 사용자에게 노출 |
| 이미 지난 예약도 취소 가능 | 지난 예약은 취소 버튼을 아예 만들지 않고, 서버에서도 막음 |
| 관리자: 날짜 드롭다운 + 같은 화면 아래 목록 | 1~12월 탭 캘린더, 날짜를 누르면 별도 목록 화면 |
| 관리자 표에 연락처 전체 노출, 상태 칸에 사유 표시 | 관리자 화면도 마스킹. 사유는 비고 칸에 2줄 '…', 누르면 전문 |
| 이름은 글자 종류 제한 없음, 010도 10자리 허용 | 이름은 한글·영문만. 010은 11자리, 예전 번호(011 등)만 10자리 허용 |

**검증하다가 찾아서 고친 결함**

- 중복 예약을 사전 조회(`exists`)로만 막으면 동시 요청이 둘 다 통과합니다. 그래서 위 표의 유니크 제약 방식으로 바꾸고 동시성 테스트를 추가했습니다.
- 연락처 검사 규칙이 화면(하이픈 위치까지 검사)과 서버(하이픈을 지운 뒤 검사)에서 달랐습니다. 둘 다 "하이픈·공백을 지운 뒤 숫자로 판단"하도록 맞췄습니다.
- 연락처를 고쳐 입력해도 이전 오류 메시지가 다음 제출 때까지 남아 있었습니다. 이제 입력하는 즉시 지웁니다.
- 비고 칸이 넘치면 다른 요소로 바꿔 그리는 바람에 크기를 재는 대상이 사라졌고, '…' 상태가 다시 꺼졌습니다. 하나의 요소를 유지하도록 고쳤습니다.
- 처리 칸 `<td>` 에 `display:flex` 를 줘서 표 구분선이 어긋났습니다. 안쪽 `<div>` 로 옮겼습니다.
- E2E 스크립트에 관리자 비밀번호 기본값이 들어가 있었습니다. "비밀번호를 코드·GitHub에 넣지 말 것" 조건에 맞춰 환경변수로만 받도록 고쳤습니다.
